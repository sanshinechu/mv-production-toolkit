## 🎵 功能說明

不憑感覺切分鏡——先「聽」歌再下刀。用 Whisper word-level 時間戳拿到每句歌詞的精確起迄，用 ffmpeg 量測逐秒音量抓出能量結構（主歌/副歌/空拍/收尾），然後讓每個 cut 的切點對齊歌詞句子與音樂重點，產出變動秒數的分鏡表。

與 mv-04（九宮格分鏡）的分工：mv-04 管「一個角色的多視角視覺設計」，本技能管「整首歌的時間軸敘事結構」。兩者可搭配使用。

## 🚀 執行流程

### Step 1：word-level 歌詞轉錄

用全域 `audio-to-srt` 技能（Groq Whisper-large-v3-turbo）：

```bash
python "%USERPROFILE%/.claude/skills/audio-to-srt/scripts/transcribe_groq.py" "歌曲.mp3" --out _subtitles/歌曲.groq.json
```

產出的 JSON 含每個字的 start/end。**歌曲轉錄常見問題**（比口語嚴重，務必逐句校對）：
- 同音誤辨：憑上下文與「唱出來的音」推正字（例：未成全→圍成圈、小孩→笑還）
- 句頭漏辨：長間奏後的第一個字常被吃掉，比對兩次轉錄結果或用能量曲線補切點
- 長音：一個字拖好幾秒（如結尾的「淚」），時間戳會很長，是正常現象

### Step 2：能量曲線分析

```bash
ffmpeg -i "歌曲.mp3" -af "asetnsamples=44100,astats=metadata=1:reset=1,ametadata=print:key=lavfi.astats.Overall.RMS_level:file=-" -f null -
```

取每秒 RMS dB 值，判讀結構：
- **主歌**：低平（約 -18 dB 上下）
- **副歌**：注意是「高原」還是「山峰」——持續高能量的段落，畫面動作量要跟著撐住，不能中途放靜謐鏡頭
- **空拍**：人聲留白處是白閃/翻頁轉場的最佳落點
- **收尾**：人聲結束點決定淡出起點，尾奏通常很短

### Step 3：產出分鏡表

輸出 Markdown 檔（`storyboard_vN.md`），必含四個區塊：

1. **歌曲結構分析**：能量曲線表 + 關鍵發現（副歌形狀、空拍位置、人聲結束點）
2. **歌詞逐句時間戳**（校正版，供字幕檔用）
3. **分鏡表**：欄位固定為 `Cut | 時間 | 秒數 | 歌詞對應 | 畫面 | 動畫 | 進/出轉場`
   - 微電影 MV 多一個**選用欄「資產狀態」**，放在「畫面」後面（見下方微電影擴充）；一般 MV 不要這一欄。
     加欄是安全的：`scripts/storyboard_md.py` 按**欄位名稱**取用（不是按位置），多的欄會忽略。
   - 切點對齊歌詞句子邊界，秒數可變動（別硬切等長）
   - 白閃壓在「進副歌」與「空拍後第二波」兩個音樂重點上
   - 動畫欄用 zoom_in / zoom_out / pan_left / pan_right（對齊 make_mv.py 詞彙）
   - 轉場欄用 fadein / fade / whiteflash / fadeout
   - 秒數合計必須等於歌曲總長（若為**微電影 MV** 含片頭前導戲 `prologue` 或片尾餘韻 `epilogue`，則 `分鏡秒數加總 = prologue + 歌曲總長 + epilogue`）
   - **單鏡秒數上限**：要丟給影片模型的 cut，單鏡 ≤10 秒（工具上限另計，最長不超過 12 秒）；長句拆成兩鏡，切在句中換氣處（2026-10-09 引自山獅霸 AI 短片工作流實測經驗，見 `docs/參考比對_山獅霸工作流.md`（01_MV製作 專案內））
   - 用靜圖＋zoom/pan 的 cut 不受此限
   - **微電影擴充（搭配 MV_13 / MV_14）**：若為微電影 MV，分鏡表可於歌曲 `0:00` 前加入 `Prologue` 鏡頭（歌詞對應欄寫 `[Prologue 口白/SFX]`），於間奏或歌尾加入 `Interlude` / `Epilogue` 鏡頭，並在分鏡表下方附上「口白與環境音效時間表（供 `mv-14` 與 `make_mv.py --audio-cues` 使用）」
   - **接手 MV_13 的資產狀態表（雙向，不要只收不回填）**：若 MV_13 區塊三有資產狀態表，分鏡定稿後要做兩件事——
     ① **回填 cut 編號**：把那張表「逐鏡狀態推進」欄裡的「初登場／轉折點／結尾」換成實際 cut 編號（MV_13 交棒時就是寫成三段，等這裡定稿才換得掉）。
     ② **填「資產狀態」欄**：每鏡只寫**跟上一鏡不同的、或這一鏡必須守住的**狀態，格式 `資產:狀態`，多個用 `｜` 分隔，例如
     `鐵捲門:升起中(由下往上)｜阿福伯:外套敞開`。方向性的敘述要寫進去，MV_06／H3 分鏡寫 `action` 時就靠這欄。
     這一欄是 MV_04／05 生該鏡首幀、以及 🅰 首幀組圖審查的核對依據，**不是裝飾**。
4. **視覺設計原則**：色調軸線 + 能量對應動作量（副歌放人物動態、主歌收尾放靜物空景；微電影額外標註正反打視線方向與關鍵信物 `[PROP_REF]` 出現鏡號）

### Step 3.5：標出「最難一鏡」

在分鏡表下方另列一行 **最難一鏡**：通常是多人同框、人物轉身／低頭再露臉、需要卡在某個字的動作、或特寫對嘴。
**正式批次生成（MV_12、生影片）前，先單獨做這一鏡**，把共通問題（角色不像、多出人、黑邊、亂碼字）在這一鏡解決。整批生完才發現共通問題是最大的浪費。

### Step 4：交付檢查

- [ ] 分鏡秒數加總 = 歌曲總長（或微電影 `prologue + 歌曲總長 + epilogue`，ffprobe 驗證）
- [ ] 每個切點都能對應到歌詞句首、音樂事件或微電影戲劇轉折點
- [ ] 要生影片的 cut 都 ≤10 秒
- [ ] 已標出「最難一鏡」
- [ ] （微電影）MV_13 資產狀態表的 cut 編號**已回填**，表上沒有還留著「初登場／轉折點／結尾」
- [ ] （微電影）分鏡表「資產狀態」欄沒有違反 MV_13 的**不可逆事項**（例如拉下的鐵門又自己升回去、脫掉的外套又自己穿回）
- [ ] 順手產出校對版 SRT（用 audio-to-srt 完整流程），字幕跟分鏡同源（微電影：歌詞 SRT 維持以歌曲開頭為 0，**不要手動平移**——`make_mv.py --sub-lyrics` 會自動加上 `+prologue`；對白 SRT 以成片時間軸為 0，另用 `--sub-dialog` 給）
