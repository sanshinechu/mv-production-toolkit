# 影片分流策略（Colab H3／Google Flow）

> 唯一正本。CLAUDE.md、MV_WORKFLOW_GUIDE、mv-06、cowrite 只放一行連到這裡，不抄內容。
> 2026-10-10 老師定案（家裡用筆電）。

## 一句話

影片提示詞三方共審「無意見」之後，**整支 MV 選一條路**：
🅰 Colab H3（Claude 代跑）或 🅱 Google Flow（老師在 Flow 平台自己生）。
兩條路的成品都放到同一個地方、同一套檔名，組裝不必分來源。

```
影片提示詞（mv-06）── cowrite --flow mv（審核模式）──「無意見」
                     │
          整支 MV 選一條路線
        ┌────────────┴────────────┐
   🅰 Colab H3                 🅱 Google Flow
   Claude 轉 H3 分鏡 JSON       cowrite --flow mv-flow --from <上一份共修>
   機器檢查（格式／秒數）        └「無意見」→ 交給老師
   清單給老師看                  老師在 Flow 生成
   老師說「直接生影片」          └ 放進 videos-raw/cutNN_*.mp4
   Claude 批次生成＋AI 放大           │
   └ collect_videos.py 搬回           │
        └────────────┬────────────┘
         collect_videos.py --check：每鏡都有、秒數夠、1080p、24 fps
                     ↓
       make_mv.py --videos 組裝（再擋一次解析度／fps）→ review_mv.py
                     ↓
       ⛔ 人工抽幀停損點：老師看 pass1／cuts 兩張圖說 OK 才算完成
```

## 共同約定（兩條路都一樣）

| 項目 | 規定 |
|---|---|
| 成品位置 | `outputs/<MV名>/videos-raw/` |
| 檔名 | `cutNN_<英文短名>.mp4`，NN 對齊分鏡表（mv-11）的 cut 編號；同一鏡重生就覆蓋，舊的自己移到 `videos-raw/_old/` |
| 規格 | 1920×1080、24 fps；秒數 **≥ 分鏡表該鏡秒數**（多的組裝時裁掉，不夠會被擋下） |
| 聲音 | H3／Veo 都會自己配聲音，**組裝時一律丟掉**，只用歌曲 |
| 角色一致 | 首幀用 mv-04／05 的單張分鏡圖；角色參考用 mv-02 的**單張半身參考圖**，不要拿左右分割的定妝圖（會被照抄成拼貼） |
| 6 項原則 | [影片製作基本原則](影片製作基本原則.md) 照舊適用 |

## 🅰 Colab H3 路線（Claude 代跑）

1. **轉 H3 分鏡 JSON**：Claude 把定案的影片提示詞逐鏡轉成 `colab_mv/inputs/<MV名>/cutNN.json`（欄位見 `colab_mv/tools/h3_shot.py` 開頭）。
   - `size` 一律 `[1344, 768]`（H3 原生短邊 768，32 的倍數，接近 16:9）。
   - `duration` = 分鏡秒數＋0.5 秒餘裕，**上限 12 秒**（超過會飄）；更長的鏡頭拆兩鏡或改用 Ken Burns。
   - 首幀放 `colab_mv/inputs/<MV名>/`，檔名 `cutNN_first.png`；需要尾幀才加 `last_frame`。
2. **機器檢查**：每個 JSON 跑 `h3_shot.py --dry-run`（官方六段格式 0 錯誤），秒數加總對分鏡表。
3. **給老師看的清單**：每鏡秒數、首幀、放大方式、預估時間（實測約 25 秒生成／1 秒影片，另加放大）、預估運算單元（A100 約 6.77／小時）。**老師說「直接生影片」才跑。**
4. **先做「最難一鏡」**（mv-11 分鏡表下方標的那一鏡）：`h3_batch.py inputs/<MV名> --only cutNN`，生完給老師看；角色不像、多出人、亂碼字這類共通問題在這一鏡解決，再跑整批。
5. **批次生成**：用 `scripts/colab_bridge.py` 接手 Colab → `setup_comfy.py --pack h3 upscale` → `tools/h3_batch.py inputs/<MV名>`（背景 nohup 跑；已成功的鏡頭自動跳過、只缺放大的只補放大，卡住就 pkill 重跑，見記憶 colab-stuck-kill-and-retry）。進度看 `colab_mv/outputs/<MV名>/progress.json`。
6. **AI 放大到 1080p**（`tools/upscale.py`，h3_batch 生完自動做）：
   - 近景、中景 → **RTX VSR**（快、不改表演）
   - 全景、舞蹈 → **FlashVSR**（較銳但會多畫細節，逐鏡抽格看）
   - 分鏡 JSON 寫 `"upscale": "rtx"` 或 `"flashvsr"`，沒寫用 rtx。
   - ⚠️ 兩套在 Colab A100 上**還沒實測**（2026-10-10），第一次用先拿一鏡比較。
7. **搬回專案**：`python scripts/collect_videos.py <MV名> --storyboard <storyboard_vN.md>` 把 `colab_mv/outputs/<MV名>/cutNN/clip_1080p.mp4` 複製成 `outputs/<MV名>/videos-raw/cutNN_*.mp4`。
8. 用完 `runtime.unassign()` 斷線。

## 🅱 Google Flow 路線（老師自己生）

1. **Flow 提示詞共審**：
   ```
   python cowrite.py "<MV名> Google Flow 提示詞" --flow mv-flow --from "<影片提示詞那份共修的資料夾名>"
   ```
   `--from` 把前面已定案的劇情、角色、場景、影片提示詞帶進來當背景，三家只審 Flow 提示詞本身。規格見 `15_ai共筆工作流/flows/specs/Google Flow提示詞.md`。
2. 「無意見」後交給老師，老師在 [Google Flow](https://labs.google/flow) 逐鏡生成：
   - 每段只能 **4／6／8 秒**，挑 ≥ 分鏡秒數的最短那個；分鏡超過 8 秒就用 Extend（只有 8 秒片段能延伸）或拆鏡。
   - 有首幀／尾幀的用 **Frames to Video**；要鎖角色用 **Ingredients to Video**（最多 3 張參考圖）。
   - 下載選 **1080p**。
3. 下載後改名 `cutNN_<短名>.mp4` 放進 `outputs/<MV名>/videos-raw/`。
4. 跟 Claude 說「Flow 影片放好了」，Claude 跑檢查（下一節）。

## 交件前檢查（兩條路共用）

```
python scripts/collect_videos.py <MV名> --storyboard outputs/<MV名>/storyboard_vN.md --check
```
擋下：缺鏡、秒數不足、不是 1920×1080、檔名對不上分鏡表。通過才組裝：
```
python scripts/make_mv.py --videos outputs/<MV名>/videos-raw --storyboard outputs/<MV名>/storyboard_vN.md --size 1920x1080 --music <歌.mp3> --out outputs/<MV名>/<MV名>_完整MV.mp4
python scripts/review_mv.py outputs/<MV名>/<MV名>_完整MV.mp4 --music <歌.mp3> --storyboard outputs/<MV名>/storyboard_vN.md
```
`make_mv.py --videos`：有 `cutNN*.mp4` 就用影片（裁到分鏡秒數、丟原聲），沒有才退回同編號的靜態圖做 Ken Burns——所以兩種素材可以混用（例如少數鏡頭沒生成成功先用圖頂著；要再加 `--shots <分鏡圖資料夾>`）。三支工具都讀同一份 `--storyboard`（`scripts/storyboard_md.py` 解析 mv-11 的分鏡表），不要各自改秒數。

`make_mv.py` 自己也會對**實際採用的每支影片**擋：低於輸出解析度（例如漏了放大的 1344×768）、不是 24 fps 都直接停下，不靠「記得先跑 --check」。真的要硬用才加 `--allow-lowres`／`--allow-fps`，並在交件紀錄寫明哪幾鏡、為什麼。

## ⛔ 人工抽幀停損點（沒過不算完成）

`review_mv.py` 全綠**不等於**可以交件——它不看字幕、亂碼、角色。照 [6 項原則](影片製作基本原則.md) 第 6 條，組裝後一定要停在這裡：

1. Claude 把 `outputs/<MV名>/review/` 的 **`<片名>_pass1.jpg`（逐鏡抽格總覽）**與 **`<片名>_cuts.jpg`（切點前後並排）** 傳給老師看（不是只說「已產出」）。
2. 逐張確認四件事：
   - **字幕帶淨空**：下方字幕區沒有重要畫面、文字被擋
   - **亂碼文字**：畫面上沒有 AI 長出來的假字、浮水印、logo
   - **角色崩壞**：臉、手、人數、服裝跟定妝一致，沒有多出人
   - **轉場**：白閃、淡入淡出落在對的地方，切點前後氣氛沒斷
3. 有問題：回到該鏡重生（🅰 `h3_batch.py --only cutNN`；🅱 老師重生）→ 重新 collect → 組裝 → 再回到第 1 步。
4. **老師明確說「抽幀確認 OK」才算完成**，並在每日筆記記下「抽幀已看、日期、誰看的」，作為交件檢查紀錄（6 項原則交件檢查最後一項）。之後才進打包／上傳。

## 怎麼選路線

| 選 Colab H3 | 選 Google Flow |
|---|---|
| 要 Claude 代跑、老師不想逐鏡操作 | 老師想親自挑每一鏡的結果 |
| 鏡頭 4–12 秒、角色特寫多 | 需要長於 12 秒的一鏡到底（Extend） |
| 扣 Colab 運算單元 | 扣 Flow 點數 |
