# 影片分流策略（Google Flow／Colab H3／Magnific／Kling.ai）

> 唯一正本。CLAUDE.md、MV_WORKFLOW_GUIDE、mv-06、cowrite 只放一行連到這裡，不抄內容。
> 2026-10-10 老師定案 🅰／🅱（家裡用筆電）；2026-10-18 加 🅲 Magnific 與 Kling 官方帳號，同日下午模型表補 Veo 3.1／PixVerse 6／Wan 3.0／Seedance 2.0（家裡用筆電，點數為當天 `simulate_cost` 實查），Kling.ai 官方帳號從備用改成獨立的 🅳 路線（老師定案）。

## 一句話

影片提示詞三方共審「無意見」之後，**整支 MV 選一條路**：
🅰 Colab H3（Claude／Codex／Antigravity 皆可代跑，用 Colab A100）、🅱 Google Flow（老師在 Flow 平台自己生）、🅲 Magnific（Claude 代跑，扣 Magnific 點數，內含 Kling／Veo／Seedance／Wan 等模型），或 🅳 Kling.ai（Claude 代跑，扣 Kling 官方帳號點數，有 Kling 4.0 與 Element 鎖角色）。
四條路的成品都放到同一個地方、同一套檔名，組裝不必分來源；也可以**主路線以外的個別鏡頭用 🅲 或 🅳 補生**（例如 H3 生不好的那一鏡）。

整張流程圖：[影片生成工作流.png](影片生成工作流.png)（原始檔 `影片生成工作流.html`，改了本文件要一起改圖）。

## 共同約定（四條路都一樣）

| 項目 | 規定 |
|---|---|
| 成品位置 | `outputs/<MV名>/videos-raw/` |
| 檔名 | `cutNN_<英文短名>.mp4`，NN 對齊分鏡表（mv-11）的 cut 編號；同一鏡重生就覆蓋，舊的自己移到 `videos-raw/_old/` |
| 規格 | 1920×1080、24 fps；秒數 **≥ 分鏡表該鏡秒數**（多的組裝時裁掉，不夠會被擋下） |
| 聲音 | H3／Veo／Kling／Seedance 都可能自己配聲音，**組裝時一律丟掉**，只用歌曲；🅲 生成時就關掉音效（`withSoundEffects: false`），能省點數；🅳 有 `enable_audio` 參數的模型一律給 `false`（預設是 `true`） |
| 角色一致 | 首幀用 mv-04／05 的單張分鏡圖；角色參考用 mv-02 的**單張半身參考圖**，不要拿左右分割的定妝圖（會被照抄成拼貼） |
| 6 項原則 | [影片製作基本原則](影片製作基本原則.md) 照舊適用 |

## 🅰 Colab H3 路線（Claude／Codex／Antigravity 皆可代跑）

> **誰能跑**：Claude、Codex、Antigravity 都可以（2026-10-18 老師確認）。三家都透過 `scripts/colab_bridge.py` 用命令列操作瀏覽器裡的 Colab，不靠各自的 Colab MCP（見記憶 colab-mcp-account-and-tab）。2026-10-09 曾查到 Codex Desktop 的 Colab MCP 是 `Unsupported`，當時寫成「只有 Claude 能接手」，但 colab_bridge.py 是命令列工具，不受這個限制。
> **成品一定要落地**：Colab 的 `/content` 是暫存，換執行階段就清空。`h3_batch.py` 的輸出直接寫進雲端 `colab_mv/outputs/`，再用 `collect_videos.py` 搬回專案；10/09 用 video maker.ipynb 生在 `/content/ComfyUI/output/` 的 H3 測試片沒有存到雲端，執行階段已換過，視為已遺失。

1. **Claude 寫 H3 分鏡初稿**：把定案的影片提示詞逐鏡轉成一份 Markdown（總表＋每鏡 `### cutNN` 加一個 ```json 區塊），格式與欄位規則照 `15_ai共筆工作流/flows/specs/H3分鏡.md`。重點：
   - `size` 一律 `[1344, 768]`（H3 原生短邊 768，32 的倍數，接近 16:9）。
   - `duration` = 分鏡秒數＋0.5 秒餘裕，**上限 12 秒**（超過會飄）；更長的鏡頭拆兩鏡或改用 Ken Burns。
   - 首幀檔名 `cutNN_first.png`；需要尾幀才加 `last_frame`（首尾幀同空間）。
   - 角色描述逐字沿用主角造型的一致性參考詞，`style` 全片逐字相同。
2. **三方審核「H3 分鏡」**（2026-10-10 老師要求加的關卡——這步要翻譯又要拆格式，最容易偏離原意）：
   ```
   python cowrite.py "<MV名> H3 分鏡" --flow mv-h3 --from "<影片提示詞那份共修>" --draft <H3 分鏡初稿.md>
   ```
   三家逐鏡比對影片提示詞（忠實、編號、秒數、JSON 合法、一致性、放大方式、禁忌），一整輪「無意見」才交給老師 ok。
3. **拆檔＋機器檢查**：
   ```
   python scripts/h3_specs_from_review.py "<H3 分鏡那份共修>" --mv <MV名> --storyboard outputs/<MV名>/storyboard_vN.md
   ```
   拆成 `colab_mv/inputs/<MV名>/cutNN.json`，同時擋：JSON 格式、欄位規則、秒數對分鏡表、H3 官方六段格式 0 錯誤。**沒過就不寫檔**，把問題當主持人意見 `--resume` 回去再審。通過會印出給老師的清單（下一步）。Claude 再把分鏡圖改名 `cutNN_first.png` 放進同一個資料夾（清單上「首幀檔在嗎」全打勾才算齊）。
4. **給老師看的清單**：每鏡秒數、首幀、放大方式、預估時間、預估運算單元（A100 約 6.77／小時）。**老師說「直接生影片」才跑。**
   - 預估時間用〈雨夜404檔案〉（2026-10-11，47 鏡）的實測：H3 每鏡約 150～340 秒，FlashVSR 放大每鏡約 290～440 秒，**一鏡合計約 7～13 分鐘**，47 鏡要跑好幾個小時。
5. **先做「最難一鏡」**（mv-11 分鏡表下方標的那一鏡）：`h3_batch.py inputs/<MV名> --only cutNN`，生完給老師看；角色不像、多出人、亂碼字這類共通問題在這一鏡解決，再跑整批。
6. **批次生成**：用 `scripts/colab_bridge.py` 接手 Colab → `setup_comfy.py --pack h3 upscale` → `tools/h3_batch.py inputs/<MV名>`（背景 nohup 跑；已成功的鏡頭自動跳過、只缺放大的只補放大，卡住就 pkill 重跑，見記憶 colab-stuck-kill-and-retry）。進度看 `colab_mv/outputs/<MV名>/progress.json`。
7. **AI 放大到 1080p**（`tools/upscale.py`，h3_batch 生完自動做）：**在 Colab A100 上只能用 FlashVSR**，每鏡分鏡 JSON 都要明寫 `"upscale": "flashvsr"`。
   - **RTX VSR 在 A100 上跑不起來**：〈雨夜404檔案〉（2026-10-11）47 鏡裡標 `rtx` 的 26 鏡全部 `upscale_failed`，錯誤都是 `NvVFXError: NvVFX_Load failed: The requested feature or capability was not found (code -14)`；標 `flashvsr` 的 21 鏡全部成功。RTX VSR 是給 RTX 系列顯卡用的，A100 是資料中心卡，推測是這個原因。那 26 鏡後來另外補出了 1080p／24 fps 的檔案，但當天筆記沒記用哪種方法補的。
   - ✅ **工具預設已改成 `flashvsr`（2026-10-18）**：`h3_batch.py` 沒寫 `upscale` 就用 flashvsr、`upscale.py --method` 預設 flashvsr；`h3_specs_from_review.py` 拆檔時遇到 `rtx` 直接退回（只接受 `flashvsr`）。`upscale.py --method rtx` 還留著，只給本機 RTX 顯卡手動用。
   - FlashVSR 會多畫一點細節，近景臉部要逐鏡抽格看；真的不行，退路是 `--method lanczos`（一般縮放，不會改畫面，但比較糊）。
   - 已經失敗的鏡頭重跑 `h3_batch.py` 會自動「只補放大」，先把那幾鏡 JSON 的 `upscale` 改成 `flashvsr` 再重跑。
8. **搬回專案**：`python scripts/collect_videos.py <MV名> --storyboard <storyboard_vN.md>` 把 `colab_mv/outputs/<MV名>/cutNN/clip_1080p.mp4` 複製成 `outputs/<MV名>/videos-raw/cutNN_*.mp4`。
9. 用完 `runtime.unassign()` 斷線。

## 🅱 Google Flow 路線（老師自己生）

1. **Flow 提示詞共審**：
   ```
   python cowrite.py "<MV名> Google Flow 提示詞" --flow mv-flow --from "<影片提示詞那份共修的資料夾名>"
   ```
   `--from` 把前面已定案的劇情、角色、場景、影片提示詞帶進來當背景，三家只審 Flow 提示詞本身。規格見 `15_ai共筆工作流/flows/specs/Google Flow提示詞.md`。
2. 「無意見」後交給老師，老師在 [Google Flow](https://labs.google/flow) 逐鏡生成：
   - 每段只能 **4／6／8 秒**，挑 ≥ 分鏡秒數的最短那個；分鏡超過 8 秒就用 Extend（只有 8 秒片段能延伸）或拆鏡。
   - 有首幀／尾幀的用 **Frames to Video**；要鎖角色用 **Ingredients to Video**（最多 3 張參考圖）。
   - **角色要開口說台詞**的鏡頭用 **Omni（1.1 Flash）**：台詞寫在提示詞裡，模型自己發聲、對嘴（〈雨停之前〉4 鏡實戰，中文對嘴自然）。多音字會唸錯，要加注音重生；聲音是模型自己生的，同一角色換一鏡可能不同聲，也不會照 SUNO 歌聲對嘴。
   - 下載選 **1080p**。
3. 下載後改名 `cutNN_<短名>.mp4` 放進 `outputs/<MV名>/videos-raw/`。
4. 跟 Claude 說「Flow 影片放好了」，Claude 跑檢查（下一節）。

### 選哪個模型（1080p、無音效，2026-10-18 `simulate_cost` 實查）

| 模型 slug | 秒數選項 | 1080p 點數 | 換算每秒 | 用途 |
|---|---|---|---|---|
| `kling-30` | 3–15 秒任選整數 | 5 秒 450／10 秒 900 | 90 | **預設**：秒數能貼分鏡表、支援首尾幀與角色參考（最多 3 張，需搭首幀） |
| `kling-25` | 只有 5／10 | 5 秒 325／10 秒 650 | 65 | Kling 裡最便宜的 1080p；分鏡秒數剛好 ≤5 或 ≤10 時用 |
| `kling-omni3` | 3–15 | 5 秒 475 | 95 | 要拿參考影片帶動作時 |
| `google-veo3_1-lite` | 只有 4／6／8 | 8 秒 320 | 40 | **最便宜的 1080p**（每秒點數不到 `kling-30` 的一半）；首尾幀可用；秒數限制跟 🅱 Flow 一樣，品質還沒試過，要用先拿一鏡比 |
| `google-veo3_1-fast` | 只有 4／6／8 | 8 秒 800 | 100 | Veo 中階，首尾幀可用、沒有參考圖 |
| `google-veo3_1` | 只有 4／6／8 | 4 秒 800／8 秒 1,600 | 200 | Veo 完整版，有參考圖；跟 🅱 Flow 同一家模型，改走 🅲 是 Claude 代跑、扣 Magnific 點數 |
| `pixverse-6` | 1–15 | 5 秒 1,000／10 秒 2,000 | 200 | 首尾幀可用、沒有參考圖，價格跟 Veo 完整版一樣，沒有特別理由就不要選 |
| `wan-3-0` | 2–30 | 5 秒 1,000／10 秒 2,000 | 200 | 單鏡最長 30 秒，參考圖最多 5 張；長鏡頭不想拆鏡時考慮 |
| `wan-3-0-prime` | 2–30 | 5 秒 1,700 | 340 | Wan 3.0 高階版 |
| `bytedance-seedance-pro-2.0` | 4–15 | 5 秒 3,500／10 秒 7,000 | 700 | 跟 2.5 差不多貴，秒數比較短，**選 2.5 就好** |
| `bytedance-seedance-pro-2.5` | 4–30 | 5 秒 3,950 | 790 | 品質最高但貴近 9 倍，只留給「最難一鏡」或重生多次仍不行的鏡頭 |
| `minimax-video-3_0-max`（H3 Max） | 5–15 | 768p 6 秒 480 | 80 | 最高只到 768p 還要放大，**通常不如直接走 🅰** |

- Veo、PixVerse、Wan、Seedance 2.0 這幾列是 2026-10-18 下午補的，條件一樣是 1080p、16:9、無音效；同一天下午也把上午那幾列（`kling-30`、`kling-25`、`kling-omni3`、Seedance 2.5、H3 Max）重新試算一次，數字沒變。
- 首尾幀：模型目錄標了「首尾幀會影響點數」（Veo、Wan 3.0、`kling-30` 都有標），但試算時塞假網址當首幀，點數都沒變。**用真的上傳圖試算才準**，列清單時逐鏡用真的首幀跑 `simulate_cost`。
- 開音效會加價（`kling-30` 5 秒從 450 變 700；`google-veo3_1-lite` 8 秒從 320 變 520），組裝本來就丟原聲，所以一律 `withSoundEffects: false`。
- 預算抓法：3 分半的 MV 約 210 秒，全用 `kling-30` ≈ 210×90 = 18,900 點（約剩餘點數的 1/8，還沒算重生）；全用 `google-veo3_1-lite` ≈ 210×40 = 8,400 點，但每鏡只能 4／6／8 秒，多的組裝時裁掉，實際會比這多一點。實際以當次 `simulate_cost` 為準，模型與價格會變。
- 模型清單會變：每次開工先 `video_models_list` 再選，不要只照這張表。

### 步驟

1. **列清單給老師看**（不扣點）：每鏡選哪個模型、秒數（≥ 分鏡秒數，取最近的可選值）、首幀圖、預估點數（逐鏡跑 `simulate_cost`，加總）。**老師說「直接生影片」才跑。**
2. **上傳首幀**：mv-04／05 的單張分鏡圖用 `creations_upload_image` 上傳，拿回的 identifier 放 `keyframes.start`（要尾幀才加 `keyframes.end`，首尾幀同空間）。
3. **先做「最難一鏡」**：`video_generate`（`aspectRatio: "16:9"`、`resolution: "1080p"`、`withSoundEffects: false`）→ `creations_wait` 等完成 → 下載給老師看；角色不像、多出人、亂碼字這類共通問題在這一鏡解決再跑整批。
4. **檢查規格**：第一鏡下載後先 `ffprobe` 看解析度與 fps。這些模型的目錄**沒有 fps 選項**，輸出是不是 24 fps 要以實測為準（2026-10-18 尚未實測）；不是 24 就轉檔：
   ```
   ffmpeg -i in.mp4 -vf fps=24 -an -c:v libx264 -crf 16 cutNN_<短名>.mp4
   ```
5. **整批生成**：一鏡一次 `video_generate`，生完下載、改名 `cutNN_<短名>.mp4` 放進 `outputs/<MV名>/videos-raw/`。
6. 跑交件前檢查（下一節）。

### 補鏡用法

主路線是 🅰、🅱 或 🅳 的 MV，某一鏡生不好時可以只把那一鏡丟給 🅲 重生，成品照同一個檔名覆蓋（舊的移到 `_old/`）。在每日筆記記下哪幾鏡是 🅲 生的。

> **誰能跑**：透過 Kling 官方 MCP（`https://kling.ai/mcp`，OAuth 免 key）。跟 🅲 一樣**每台各自接並授權**；2026-10-18 只有家裡用筆電接好（Claude Code、Codex），見記憶 kling-mcp-setup。
> **點數**：老師的 kling.ai 帳號 2026-10-18 實查是會員（`membershipType VIP`，方案說明 Standard），剩 **660 點**，只有 Magnific 的零頭。
> **為什麼獨立成一條路**：Magnific 只叫得到 Kling 2.5～3.0，官方帳號多了兩樣——**Kling 4.0**（單鏡 3～30 秒，首尾幀之外還能塞中間關鍵幀）和 **Element**（把主角建成可重複用的「主體」，每鏡用編號叫出來，鎖角色比每次塞參考圖穩）。

### 選哪個模型（2026-10-18 `who_am_i` 實查）

| 模型 | 工具 | 秒數 | 解析度 | 首尾幀 | Element | 用途 |
|---|---|---|---|---|---|---|
| `kling-video-v4_0` | `image_to_video` | 3–30 | 720p／1080p | 首幀＋尾幀＋中間關鍵幀，合計最多 10 張 | ✗ | 長鏡頭、動作要照幾張圖走；**預設 720p，要明寫 `1080p`** |
| `kling-video-v4_0` | `omni_ref_video` | 3–30 | 720p／1080p | 圖片當參考，不是首幀 | ✓ 最多 7 個 | **Kling 4.0＋Element 要走這個工具**；一樣**預設 720p，要明寫 `1080p`**；`prefer_multi_shots` 一定要 `true`，不能關；按秒計費，輸入的參考影片長度也算進去 |
| `kling-video-v3_0` | `image_to_video` | 3–15 | 720p／1080p／4K | 首幀＋尾幀 | ✓ 最多 3 個 | 首幀固定構圖，又要用 Element 鎖臉；`prefer_multi_shots` 預設 `true` |
| `kling-video-v3_0_omni` | `image_to_video` | 3–15 | 720p／1080p／4K | 多張參考圖（最多 7 張） | ✓ 最多 7 個 | 多個角色同框 |
| `kling-video-v3_0_turbo` | `image_to_video` | 3–15 | 720p／1080p | 只有首幀 | ✗ | 官方說單張圖轉影片的首選 |

- **點數待第一鏡實測**：官方 MCP 沒有試算工具（不像 🅲 有 `simulate_cost`），每鏡扣幾點只能生了才知道。
- **秒數要用整數字串**（例如 `"8"`），一次只生一支：`imageCount` 可以填 1～4，保持預設 `1` 不要改（一次出好幾支會多扣多少還沒實測）。
- 模型清單會變：每次開工先跑 `who_am_i` 看現在有哪些模型、參數是什麼，不要只照這張表。

### 步驟

1. **查點數與模型**（不扣點）：`query_membership_and_credits` 記下目前點數，`who_am_i` 確認要用的模型參數。
2. **建 Element（要鎖角色時）**：mv-02 的**單張半身參考圖**用 `file_upload` 上傳 → `element_create` 建成主體 → 把 id 記在每日筆記與該 MV 的 HANDOFF.md，之後每鏡共用（`element_list` 查得到）。提示詞裡用 `<<<id>>>` 叫它，再把 id 填進 `elements`；只有模型表 Element 欄打勾的才能用。
3. **上傳首幀**：mv-04／05 的單張分鏡圖用 `file_upload` 上傳（不能直接給本機路徑），拿回的網址填 `first_image`（要尾幀才加 `tail_image`，首尾幀同空間）。走 `omni_ref_video` 的話沒有 `first_image`，圖片填 `image_1`，而且只當參考、不是首幀，構圖不一定照著圖。
4. **列清單給老師看**：每鏡選哪個模型、秒數（≥ 分鏡秒數）、首幀、要不要 Element。點數那欄寫「待第一鏡實測」。**老師說「直接生影片」才跑。**
5. **先做「最難一鏡」並量點數**：生成前後各查一次 `query_membership_and_credits`，相減就是這一鏡的點數 → 寫回本節的模型表（模型、秒數、解析度、點數、日期）→ 再拿這個數字估整批。**660 點不一定夠整支 MV**，估出來不夠就跟老師講，改成只用 🅳 補幾個關鍵鏡頭，其餘走別條路。
6. **檢查規格**：下載後 `ffprobe` 看解析度與 fps（2026-10-18 尚未實測）。不是 24 fps 就照 🅲 的轉檔指令處理；如果拿到的是 720p，代表漏寫 `1080p`，**回去用 1080p 重生**，不要用 ffmpeg 硬拉大（會糊）。
7. **整批生成**：一鏡一次，用 `query_tasks` 查進度，下載後改名 `cutNN_<短名>.mp4` 放進 `outputs/<MV名>/videos-raw/`。
8. 跑交件前檢查（下一節）。

## 交件前檢查（四條路共用）

```
python scripts/collect_videos.py <MV名> --storyboard outputs/<MV名>/storyboard_vN.md --check
```

擋下：缺鏡、秒數不足、不是 1920×1080、不是 24 fps、檔名對不上分鏡表。通過才組裝：

```
python scripts/make_mv.py --videos outputs/<MV名>/videos-raw --storyboard outputs/<MV名>/storyboard_vN.md --size 1920x1080 --music <歌.mp3> --out outputs/<MV名>/<MV名>_完整MV.mp4
python scripts/review_mv.py outputs/<MV名>/<MV名>_完整MV.mp4 --music <歌.mp3> --storyboard outputs/<MV名>/storyboard_vN.md
```

`make_mv.py --videos`：有 `cutNN*.mp4` 就用影片（裁到分鏡秒數、丟原聲），沒有才退回同編號的靜態圖做 Ken Burns——所以兩種素材可以混用（例如少數鏡頭沒生成成功先用圖頂著；要再加 `--shots <分鏡圖資料夾>`）。三支工具都讀同一份 `--storyboard`（`scripts/storyboard_md.py` 解析 mv-11 的分鏡表），不要各自改秒數。

`make_mv.py` 自己也會對**實際採用的每支影片**擋：低於輸出解析度（例如漏了放大的 1344×768）、不是 24 fps 都直接停下，不靠「記得先跑 --check」。真的要硬用才加 `--allow-lowres`／`--allow-fps`，並在交件紀錄寫明哪幾鏡、為什麼。

## ⛔ 人工抽幀停損點（沒過不算完成）

`review_mv.py` 全綠**不等於**可以交件——它不看字幕、亂碼、角色。照 [6 項原則](影片製作基本原則.md) 第 6 條，組裝後一定要停在這裡：

1. Claude 把 `outputs/<MV名>/review/` 的 **`<片名>_pass1.jpg`（逐鏡抽格總覽）**與 **`<片名>_cuts.jpg`（切點前後並排）** 傳給老師看（不是只說「已產出」）。
2. 逐張確認四件事：
   - **字幕帶淨空**：下方字幕區沒有重要畫面、文字被擋
   - **亂碼文字**：畫面上沒有 AI 長出來的假字、浮水印、logo
   - **角色崩壞**：臉、手、人數、服裝跟定妝一致，沒有多出人
   - **轉場**：白閃、淡入淡出落在對的地方，切點前後氣氛沒斷
3. 有問題：回到該鏡重生（🅰 `h3_batch.py --only cutNN`；🅱 老師重生；🅲 該鏡重跑 `video_generate`；🅳 該鏡用原本的工具重跑（`image_to_video` 或 `omni_ref_video`）；任何路線都可以改用 🅲 或 🅳 補這一鏡）→ 重新 collect → 組裝 → 再回到第 1 步。
4. **老師明確說「抽幀確認 OK」才算完成**，並在每日筆記記下「抽幀已看、日期、誰看的」，作為交件檢查紀錄（6 項原則交件檢查最後一項）。之後才進打包／上傳。
