# 影片分流策略（Colab H3／Google Flow／Magnific）

> 唯一正本。CLAUDE.md、MV_WORKFLOW_GUIDE、mv-06、cowrite 只放一行連到這裡，不抄內容。
> 2026-10-10 老師定案 🅰／🅱（家裡用筆電）；2026-10-18 加 🅲 Magnific 與 Kling 官方帳號（家裡用筆電，點數為當天 `simulate_cost` 實查）。

## 一句話

影片提示詞三方共審「無意見」之後，**整支 MV 選一條路**：
🅰 Colab H3（Claude 代跑）、🅱 Google Flow（老師在 Flow 平台自己生）或 🅲 Magnific（Claude 代跑，扣 Magnific 點數，內含 Kling／Seedance 等模型）。
三條路的成品都放到同一個地方、同一套檔名，組裝不必分來源；也可以**主路線以外的個別鏡頭用 🅲 補生**（例如 H3 生不好的那一鏡）。

```
影片提示詞（mv-06）── cowrite --flow mv（審核模式）──「無意見」
                     │
               整支 MV 選一條路線
     ┌───────────────┼──────────────────┐
🅰 Colab H3        🅱 Google Flow          🅲 Magnific
Claude 寫 H3 分鏡   cowrite --flow mv-flow  Claude 選模型＋simulate_cost 試算
三方審核「H3 分鏡」 --from <上一份共修>      清單給老師看（含點數）
拆檔＋機器檢查      └「無意見」→ 交給老師    老師說「直接生影片」
清單給老師看        老師在 Flow 生成         先生最難一鏡 → 整批
老師說「直接生影片」└ 放進 videos-raw/       下載改名放進 videos-raw/
Claude 批次＋AI 放大       │                       │
└ collect_videos.py 搬回   │                       │
     └───────────────┼──────────────────┘
         collect_videos.py --check：每鏡都有、秒數夠、1080p、24 fps
                     ↓
       make_mv.py --videos 組裝（再擋一次解析度／fps）→ review_mv.py
                     ↓
       ⛔ 人工抽幀停損點：老師看 pass1／cuts 兩張圖說 OK 才算完成
```

## 共同約定（三條路都一樣）

| 項目 | 規定 |
|---|---|
| 成品位置 | `outputs/<MV名>/videos-raw/` |
| 檔名 | `cutNN_<英文短名>.mp4`，NN 對齊分鏡表（mv-11）的 cut 編號；同一鏡重生就覆蓋，舊的自己移到 `videos-raw/_old/` |
| 規格 | 1920×1080、24 fps；秒數 **≥ 分鏡表該鏡秒數**（多的組裝時裁掉，不夠會被擋下） |
| 聲音 | H3／Veo／Kling／Seedance 都可能自己配聲音，**組裝時一律丟掉**，只用歌曲；🅲 生成時就關掉音效（`withSoundEffects: false`），能省點數 |
| 角色一致 | 首幀用 mv-04／05 的單張分鏡圖；角色參考用 mv-02 的**單張半身參考圖**，不要拿左右分割的定妝圖（會被照抄成拼貼） |
| 6 項原則 | [影片製作基本原則](影片製作基本原則.md) 照舊適用 |

## 🅰 Colab H3 路線（Claude 代跑）

> **誰能跑**：只有 Claude Code（透過 `scripts/colab_bridge.py` 操作瀏覽器裡的 Colab，見記憶 colab-mcp-account-and-tab）。Codex Desktop 的 Colab MCP 是 `Unsupported`（2026-10-09 查證），Codex 只能做共審與文件，不要叫它接手 Colab。
> **成品一定要落地**：Colab 的 `/content` 是暫存，換執行階段就清空。`h3_batch.py` 的輸出直接寫進雲端 `colab_mv/outputs/`，再用 `collect_videos.py` 搬回專案；10/09 用 video maker.ipynb 生在 `/content/ComfyUI/output/` 的 H3 測試片沒有存到雲端，執行階段已換過，視為已遺失。

1. **Claude 寫 H3 分鏡初稿**：把定案的影片提示詞逐鏡轉成一份 Markdown（總表＋每鏡 `### cutNN` 加一個 ```json 區塊），格式與欄位規則照 `15_ai共筆工作流/flows/specs/H3分鏡.md`。重點：
   - `size` 一律 `[1344, 768]`（H3 原生短邊 768，32 的倍數，接近 16:9）。
   - `duration` = 分鏡秒數＋0.5 秒餘裕，**上限 12 秒**（超過會飄）；更長的鏡頭拆兩鏡或改用 Ken Burns。
   - 首幀檔名 `cutNN_first.png`；需要尾幀才加 `last_frame`（首尾幀同空間）。
   - 角色描述逐字沿用主角造型的一致性參考詞，`style` 全片逐字相同。
2. **三方審核「H3 分鏡」**（2026-10-10 老師要求加的關卡——這步要翻譯又要拆格式，最容易偏離原意）：
   ```
   python cowrite.py "<MV名> H3 分鏡" --flow mv-h3 --from "<影片提示詞那份共修>" --draft <H3 分鏡初稿.md>
   ```
   三家逐鏡比對影片提示詞（忠實、編號、秒數、JSON 合法、一致性、放大方式、禁忌），一整輪「無意見」才交給老師 ok。
3. **拆檔＋機器檢查**：
   ```
   python scripts/h3_specs_from_review.py "<H3 分鏡那份共修>" --mv <MV名> --storyboard outputs/<MV名>/storyboard_vN.md
   ```
   拆成 `colab_mv/inputs/<MV名>/cutNN.json`，同時擋：JSON 格式、欄位規則、秒數對分鏡表、H3 官方六段格式 0 錯誤。**沒過就不寫檔**，把問題當主持人意見 `--resume` 回去再審。通過會印出給老師的清單（下一步）。Claude 再把分鏡圖改名 `cutNN_first.png` 放進同一個資料夾（清單上「首幀檔在嗎」全打勾才算齊）。
4. **給老師看的清單**：每鏡秒數、首幀、放大方式、預估時間（實測約 25 秒生成／1 秒影片，另加放大）、預估運算單元（A100 約 6.77／小時）。**老師說「直接生影片」才跑。**
5. **先做「最難一鏡」**（mv-11 分鏡表下方標的那一鏡）：`h3_batch.py inputs/<MV名> --only cutNN`，生完給老師看；角色不像、多出人、亂碼字這類共通問題在這一鏡解決，再跑整批。
6. **批次生成**：用 `scripts/colab_bridge.py` 接手 Colab → `setup_comfy.py --pack h3 upscale` → `tools/h3_batch.py inputs/<MV名>`（背景 nohup 跑；已成功的鏡頭自動跳過、只缺放大的只補放大，卡住就 pkill 重跑，見記憶 colab-stuck-kill-and-retry）。進度看 `colab_mv/outputs/<MV名>/progress.json`。
7. **AI 放大到 1080p**（`tools/upscale.py`，h3_batch 生完自動做）：
   - 近景、中景 → **RTX VSR**（快、不改表演）
   - 全景、舞蹈 → **FlashVSR**（較銳但會多畫細節，逐鏡抽格看）
   - 分鏡 JSON 寫 `"upscale": "rtx"` 或 `"flashvsr"`，沒寫用 rtx。
   - ⚠️ 兩套在 Colab A100 上**還沒實測**（2026-10-10），第一次用先拿一鏡比較。
8. **搬回專案**：`python scripts/collect_videos.py <MV名> --storyboard <storyboard_vN.md>` 把 `colab_mv/outputs/<MV名>/cutNN/clip_1080p.mp4` 複製成 `outputs/<MV名>/videos-raw/cutNN_*.mp4`。
9. 用完 `runtime.unassign()` 斷線。

## 🅱 Google Flow 路線（老師自己生）

1. **Flow 提示詞共審**：
   ```
   python cowrite.py "<MV名> Google Flow 提示詞" --flow mv-flow --from "<影片提示詞那份共修的資料夾名>"
   ```
   `--from` 把前面已定案的劇情、角色、場景、影片提示詞帶進來當背景，三家只審 Flow 提示詞本身。規格見 `15_ai共筆工作流/flows/specs/Google Flow提示詞.md`。
2. 「無意見」後交給老師，老師在 [Google Flow](https://labs.google/flow) 逐鏡生成：
   - 每段只能 **4／6／8 秒**，挑 ≥ 分鏡秒數的最短那個；分鏡超過 8 秒就用 Extend（只有 8 秒片段能延伸）或拆鏡。
   - 有首幀／尾幀的用 **Frames to Video**；要鎖角色用 **Ingredients to Video**（最多 3 張參考圖）。
   - 下載選 **1080p**。
3. 下載後改名 `cutNN_<短名>.mp4` 放進 `outputs/<MV名>/videos-raw/`。
4. 跟 Claude 說「Flow 影片放好了」，Claude 跑檢查（下一節）。

## 🅲 Magnific 路線（Claude 代跑）

> **誰能跑**：透過 Magnific MCP（`https://mcp.magnific.com`，OAuth 免 key）。MCP 設定不走 chezmoi，**每台各自 `claude mcp add` 並授權**；2026-10-18 只有家裡用筆電接好（Claude Code／Codex／Antigravity 三套）。見記憶 magnific-video-music-only。
> **點數**：Premium 方案，2026-10-18 剩 151,204 點（總額 240,000）。老師分工：Magnific 點數**只用在影片與音樂**，生圖照舊走免費管道。

### 選哪個模型（1080p、無音效，2026-10-18 `simulate_cost` 實查）

| 模型 slug | 秒數選項 | 1080p 點數 | 換算每秒 | 用途 |
|---|---|---|---|---|
| `kling-30` | 3–15 秒任選整數 | 5 秒 450／10 秒 900 | 90 | **預設**：秒數能貼分鏡表、支援首尾幀與角色參考（最多 3 張，需搭首幀） |
| `kling-25` | 只有 5／10 | 5 秒 325／10 秒 650 | 65 | 最便宜的 1080p；分鏡秒數剛好 ≤5 或 ≤10 時用 |
| `kling-omni3` | 3–15 | 5 秒 475 | 95 | 要拿參考影片帶動作時 |
| `bytedance-seedance-pro-2.5` | 4–30 | 5 秒 3,950 | 790 | 品質最高但貴近 9 倍，只留給「最難一鏡」或重生多次仍不行的鏡頭 |
| `minimax-video-3_0-max`（H3 Max） | 5–15 | 768p 6 秒 480 | 80 | 最高只到 768p 還要放大，**通常不如直接走 🅰** |

- 開音效會加價（`kling-30` 5 秒從 450 變 700），組裝本來就丟原聲，所以一律 `withSoundEffects: false`。
- 預算抓法：3 分半的 MV 約 210 秒，全用 `kling-30` ≈ 210×90 = 18,900 點（約剩餘點數的 1/8，還沒算重生）。實際以當次 `simulate_cost` 為準，模型與價格會變。
- 模型清單會變：每次開工先 `video_models_list` 再選，不要只照這張表。

### 步驟

1. **列清單給老師看**（不扣點）：每鏡選哪個模型、秒數（≥ 分鏡秒數，取最近的可選值）、首幀圖、預估點數（逐鏡跑 `simulate_cost`，加總）。**老師說「直接生影片」才跑。**
2. **上傳首幀**：mv-04／05 的單張分鏡圖用 `creations_upload_image` 上傳，拿回的 identifier 放 `keyframes.start`（要尾幀才加 `keyframes.end`，首尾幀同空間）。
3. **先做「最難一鏡」**：`video_generate`（`aspectRatio: "16:9"`、`resolution: "1080p"`、`withSoundEffects: false`）→ `creations_wait` 等完成 → 下載給老師看；角色不像、多出人、亂碼字這類共通問題在這一鏡解決再跑整批。
4. **檢查規格**：第一鏡下載後先 `ffprobe` 看解析度與 fps。這些模型的目錄**沒有 fps 選項**，輸出是不是 24 fps 要以實測為準（2026-10-18 尚未實測）；不是 24 就轉檔：
   ```
   ffmpeg -i in.mp4 -vf fps=24 -an -c:v libx264 -crf 16 cutNN_<短名>.mp4
   ```
5. **整批生成**：一鏡一次 `video_generate`，生完下載、改名 `cutNN_<短名>.mp4` 放進 `outputs/<MV名>/videos-raw/`。
6. 跑交件前檢查（下一節）。

### 補鏡用法

主路線是 🅰 或 🅱 的 MV，某一鏡生不好時可以只把那一鏡丟給 🅲 重生，成品照同一個檔名覆蓋（舊的移到 `_old/`）。在每日筆記記下哪幾鏡是 🅲 生的。

### Kling 官方帳號（備用，不是第四條路線）

老師另有 kling.ai 帳號（Standard 方案，2026-10-18 約 660 點），MCP 是 `https://kling.ai/mcp`（家裡用筆電已接，見記憶 kling-mcp-setup）。**Magnific 已經能叫 Kling 2.5～3.0**，點數也多得多，所以平常走 🅲；只有 Magnific 沒有的功能（例如官方的 Element 主體管理）才考慮用官方帳號。官方帳號每支扣幾點、輸出規格都**還沒實測**，要用之前先用不扣點的工具（`who_am_i` 一類）查清楚。

## 交件前檢查（三條路共用）

```
python scripts/collect_videos.py <MV名> --storyboard outputs/<MV名>/storyboard_vN.md --check
```
擋下：缺鏡、秒數不足、不是 1920×1080、檔名對不上分鏡表。通過才組裝：
```
python scripts/make_mv.py --videos outputs/<MV名>/videos-raw --storyboard outputs/<MV名>/storyboard_vN.md --size 1920x1080 --music <歌.mp3> --out outputs/<MV名>/<MV名>_完整MV.mp4
python scripts/review_mv.py outputs/<MV名>/<MV名>_完整MV.mp4 --music <歌.mp3> --storyboard outputs/<MV名>/storyboard_vN.md
```
`make_mv.py --videos`：有 `cutNN*.mp4` 就用影片（裁到分鏡秒數、丟原聲），沒有才退回同編號的靜態圖做 Ken Burns——所以兩種素材可以混用（例如少數鏡頭沒生成成功先用圖頂著；要再加 `--shots <分鏡圖資料夾>`）。三支工具都讀同一份 `--storyboard`（`scripts/storyboard_md.py` 解析 mv-11 的分鏡表），不要各自改秒數。

`make_mv.py` 自己也會對**實際採用的每支影片**擋：低於輸出解析度（例如漏了放大的 1344×768）、不是 24 fps 都直接停下，不靠「記得先跑 --check」。真的要硬用才加 `--allow-lowres`／`--allow-fps`，並在交件紀錄寫明哪幾鏡、為什麼。

## ⛔ 人工抽幀停損點（沒過不算完成）

`review_mv.py` 全綠**不等於**可以交件——它不看字幕、亂碼、角色。照 [6 項原則](影片製作基本原則.md) 第 6 條，組裝後一定要停在這裡：

1. Claude 把 `outputs/<MV名>/review/` 的 **`<片名>_pass1.jpg`（逐鏡抽格總覽）**與 **`<片名>_cuts.jpg`（切點前後並排）** 傳給老師看（不是只說「已產出」）。
2. 逐張確認四件事：
   - **字幕帶淨空**：下方字幕區沒有重要畫面、文字被擋
   - **亂碼文字**：畫面上沒有 AI 長出來的假字、浮水印、logo
   - **角色崩壞**：臉、手、人數、服裝跟定妝一致，沒有多出人
   - **轉場**：白閃、淡入淡出落在對的地方，切點前後氣氛沒斷
3. 有問題：回到該鏡重生（🅰 `h3_batch.py --only cutNN`；🅱 老師重生；🅲 該鏡重跑 `video_generate`，或任何路線都可以改用 🅲 補這一鏡）→ 重新 collect → 組裝 → 再回到第 1 步。
4. **老師明確說「抽幀確認 OK」才算完成**，並在每日筆記記下「抽幀已看、日期、誰看的」，作為交件檢查紀錄（6 項原則交件檢查最後一項）。之後才進打包／上傳。

## 怎麼選路線

| | 🅰 Colab H3 | 🅱 Google Flow | 🅲 Magnific |
|---|---|---|---|
| 誰操作 | Claude 代跑 | 老師自己逐鏡生 | Claude 代跑 |
| 適合 | 角色特寫多、想省點數 | 老師想親自挑每一鏡 | 要直接出 1080p、不想接手 Colab；或補別條路生不好的鏡頭 |
| 每鏡秒數 | 4–12 | 4／6／8（Extend 可更長） | `kling-30` 3–15 任選 |
| 輸出 | 1344×768，要 AI 放大 | 1080p | 1080p（fps 待實測） |
| 扣什麼 | Colab 運算單元 | Flow 點數 | Magnific 點數（`kling-30` 約 90 點／秒） |
| 哪些機器能跑 | 看 Colab 連得上的機器 | 任何有瀏覽器的 | 有接 Magnific MCP 的（2026-10-18 只有家裡用筆電） |
