## 先分清楚：兩邊在做不一樣的東西

| | 山獅霸 | 我們的 MV |
|---|---|---|
| 片種 | 劇情喜劇，有對白、要對嘴 | 音樂錄影帶，歌聲為主，很少講話 |
| 畫面怎麼切 | 依台詞和劇情 | 依歌詞句子和音樂能量（mv-11） |
| 影片模型 | 本機 MiniMax H3（要 16 GB 顯存） | 雲端 Kling／Hailuo／Seedance、Google Flow，本機 Wan 試行中 |
| 生圖 | 本機 Qwen-Image／Qwen-Image-Edit | Cloudflare flux（免費）、Vertex（付費） |
| 聲音 | BreezyVoice 念台詞＋Music 3 配樂 | SUNO／ACE-Step 唱整首歌 |
| 我們的顯卡 | — | 4060 筆電 8 GB，**跑不了 H3** |

所以要借的是**規則背後的道理和檢查方法**，不是照搬他們的模型。

## 1. 規則與踩坑 → 對到 mv-02／03／06／09／12

分成「不管用哪個影片模型都成立」和「只對 H3 成立」兩類。前一類才值得收進來。

### 通用、值得收的

| 山獅霸的規則 | 背後的道理 | 對到我們哪裡 | 我們現況 |
|---|---|---|---|
| 單人鏡提示詞完全不提其他人；多人鏡寫 `Exactly N people` | 提到誰誰就冒出來 | mv-03、mv-06 | 沒有這條 → **建議補** |
| 提示詞必寫 `NO black letterbox bars` | 寫「電影感」模型就自己加黑邊 | mv-06、mv-10（打光指令都是電影感用語） | 沒有 → **建議補** |
| 沒有尾幀的鏡頭加「LOCKED-OFF STATIC CAMERA on a tripod」 | 不鎖的話鏡頭自己漂走 | mv-06（想要靜止鏡頭時） | mv-06 只教怎麼加運鏡，沒教怎麼**讓鏡頭不動** → 建議補 |
| 首尾幀：構圖要一樣，但**不能是同一張圖** | 構圖不同 → 模型會搖鏡去湊；同一張 → 畫面凍住 | mv-06（同場景的連續動作）。**不適用 mv-09**：mv-09 本來就是故意換場景做轉場 | mv-09 已寫「首尾幀主角外觀要一致、場景要有視覺聯繫」✅；mv-06 若要用首尾幀鎖動作，可補這條 |
| 不同機位的首幀從**同一張底圖**改 | 換機位背景會跑掉 | mv-04 | ✅ 2026-10-09 已寫進 mv-04；同日 mv-04 也改成**各自生成 9 張**（不再一張大圖切 9 格） |
| 每鏡都**照抄**角色的鎖定外觀描述，不自己重寫 | 重寫一次就漂一次 | mv-02 的 `[CHARACTER_REF]` | 已經有 ✅ |
| **生圖參考圖只能用單張半身照，不要用多格定妝表** | 模型會把多格版面照抄成拼貼 | ⚠️ **mv-02 正好是 Split Screen（臉＋全身兩格）** | **潛在衝突**：Split Screen 適合給人看，但拿去當生圖參考可能會被照抄成兩格。建議 mv-02 多產一張「單張半身」專門當參考圖 |
| 畫面上的中文一律後製疊字 | 模型寫中文會變亂碼 | 影片製作基本原則第 5 條、mv-12 風格鐵律 | 已經有 ✅ |
| 人物不要橫向走，改原地轉身 | 模型會跟拍，背景跟著滑 | mv-06 | 沒有 → 可補 |
| 低頭、轉身之後臉會換人 → 另生一張「動作結束時」的尾幀鎖住 | 臉轉開再轉回來就不是同一個人 | mv-06、mv-09 | 沒有 → 可補 |
| 主角在腰部以上（臉要佔畫面高度 10% 以上） | 解析度低的全景臉會糊，放大救不回 | mv-04、mv-11 分鏡設計 | MV 很愛遠景空拍（mv-08）→ 遠景鏡**不要拍臉**就好 |
| 單鏡 ≤12 秒，短鏡也至少生 5 秒再剪 | 太長會漂移、自己切鏡 | mv-11 分鏡秒數 | mv-11 的秒數是依歌詞切的，長句要拆成兩鏡 → 建議在 mv-11 加上限 |
| **先做最難的一鏡再批次** | 整批生完才發現共通問題最浪費（他們 13 鏡累積了 25 版） | mv-12 批次生圖、Step 7 影片生成 | mv-12 是直接整批跑 → **建議加「先試 1–2 鏡」關卡** |
| 重拍時開新資料夾、換新 seed | 用舊資料夾重跑結果一模一樣 | mv-12（已存在就跳過的機制） | mv-12 是「刪掉再重跑」，原理相同 ✅ |

### 只對 H3 成立、不用收的

DMAD 4 步、靜音引導音軌、動作 LoRA 強度、`h3_shot.py` 六段提示詞格式、ComfyUI `/history` 計時等。我們沒有 H3，先跳過。哪天主機 1 評估可行再回頭看。

## 2. 聲音：BreezyVoice 和配樂做法

### BreezyVoice 對 MV 的價值不高

MV 的人聲是 SUNO／ACE-Step **唱**出來的，BreezyVoice 是**念**台詞的，用途不一樣。它比較適合：
- MV 裡的口白段（開場一句話、歌曲中間的獨白）
- 教學影片旁白（`scratch-editor-video`、`hyperframes-teaching-video`）

它的「自動挑選」想法倒是可以借：**同一句生 8 個候選 → 用語音辨識（ASR）確認字和聲調都對 → 再比腔調分數**。我們 mv-11 用 Whisper 轉錄歌詞，也可以拿來檢查 SUNO 有沒有唱錯字（唱錯的版本直接淘汰，不必人一首一首聽）。

### 配樂與混音：這段**直接能用**

| 山獅霸做法 | 對到我們哪裡 | 怎麼用 |
|---|---|---|
| 配樂同一段生 3 個 seed，用 BS-RoFormer 分離，挑人聲殘留最少的 | 我們已經有 `tools/demucs-env` | 做純音樂版（伴奏、片頭片尾）時照這個挑 |
| 響度兩段式：loudnorm → 量測 → 補差 → 限幅，目標約 −15.5 LUFS、峰值 −2 dBFS 以下 | Step 10 FFmpeg 組裝 | **建議收進組裝腳本** |
| **`alimiter` 一定要加 `level=false`** | 同上 | 預設值會把音量自動拉到 0 dBFS 爆掉，**而且不會報錯**——跟我們踩過的「安靜地出錯」同一類坑 |
| 台詞（口白）期間背景音樂壓到 15–30% | MV 口白段 | 只有口白時用 |
| 音效用 CC0 音效庫，不用程式合成 | MV 環境音 | zip 裡附了 58 個 Freesound CC0 音效（腳步、翻頁、門、歡呼、操場…），**很多是校園場景**，可以直接拿來用 |
| 同時輸出手機版 720p（<30 MB）給人驗收 | Step 11 打包 | 給老師或學生先看時很方便 |

> 響度目標：YouTube 的標準是 −14 LUFS，他們選 −15.5 是留一點餘裕。我們要定哪個值，實測後再決定。

## 3. 自審五遍 → MV 版自審清單

我們的 [影片製作基本原則](影片製作基本原則.md) 第 6 條已經要求交件前抽幀，方向一樣。山獅霸多做的是**把檢查寫成腳本**，而且分成五遍。改成 MV 版如下：

| 遍 | 山獅霸檢查什麼 | MV 版改成 | 現有工具 |
|---|---|---|---|
| 1 | 每鏡抽 4 格拼總覽圖，逐張人工看 | 一樣。重點看：多手多腳、臉換人、背景冒人、畫面出現亂碼字 | mv-12 已有 ffmpeg tile 拼圖 ✅ |
| 2 | 每句台詞在成片 ASR 一次 | 歌詞字幕跟實際唱的對不對得上（時間軸、錯字） | mv-11 的 Whisper 時間戳、`subtitle-review` |
| 3 | 色度雜訊（跟首幀比） | AI 影片常見的閃爍、油畫雜訊 | 沒有 → 可參考 `noise_scan.py` |
| 4 | 黑畫面、定格超過 0.8 秒、響度、峰值 | 一樣 | ffmpeg `blackdetect`、`freezedetect`、`ebur128` |
| 5 | 切點前後對照圖、接點明暗差 >12 就警告 | **加一項 MV 專屬：切點有沒有落在 mv-11 指定的拍點／句首** | 沒有 → 可寫 |

### 他們的原則裡，最值得抄的三句

1. **交給人看之前，自己先審完、修完**。人只判斷主觀的部分（好不好看、情緒對不對）。
2. **至少看一張原尺寸的全畫面**。只看縮圖會漏掉第三條腿和雜訊。
3. **技術檢查通過 ≠ 使用者驗收通過**，兩個分開記。沒量的東西照實寫「沒量」。

> 第 3 句跟我們基本原則的「未實際抽幀檢查不得宣稱已通過」是同一個精神，可以互相引用。

### MV 版常退件清單（草稿，待老師補）

- [ ] 多手多腳、手指數不對
- [ ] 臉跟定妝照不像、前後鏡換人
- [ ] 背景冒出人、人突然消失
- [ ] 畫面出現亂碼字（黑板、招牌、衣服）
- [ ] 鏡頭自己漂走，或該動卻沒動
- [ ] 加了黑邊（letterbox）
- [ ] 切點沒對到拍子
- [ ] 歌詞字幕錯字或時間不對
- [ ] 字幕遮住重點畫面（基本原則第 1 條）
- [ ] 響度忽大忽小、峰值爆音

## 4. 知識層：專案 CLAUDE.md 的寫法

山獅霸的心得是：**品質提升有一半以上來自知識層，不是換模型**。他們的做法跟我們的 LifeOS 很像，但有幾點我們 MV 專案還沒做到：

| 他們的做法 | 我們 MV 專案現況 | 建議 |
|---|---|---|
| **最新決策寫在 CLAUDE.md 最上面**，每條寫日期、結論、連結；舊的不刪，標「已被取代」 | MV 的 `CLAUDE.md` 開頭是身份介紹和 12 步流程說明，最近的決策（ACE-Step、哼唱導引、Wan 試行）散在工作日誌裡 | 在最上面加一個「最新決策」區 |
| 「**已否決的做法**」表格（做法＋原因） | 沒有 | 加一張，例如：免費模型不畫寫實人臉（mv-12 已有這條，可以集中列出來） |
| 四種狀態分開寫：**查閱過／裝了／實測過／使用者驗收過** | 混在一起 | 寫進文件時標清楚（像本文件開頭的「狀態」那行） |
| **退件一次就寫一條 feedback 記憶** | 全域記憶有這個機制 | MV 的退件理由也照做 |
| 同一件事只有一個詳細來源，其他地方只放連結 | MV 的 `CLAUDE.md` **把全域 CLAUDE.md 的身份、語言規範整段抄了一份** | ⚠️ 這就是我們候選碟清單踩過的「十處四版」坑。建議改成一句「遵守全域設定」，不要重抄 |

## 不要照搬的

- **H3、DMAD、Qwen 本機生圖**：要 16 GB 顯存，兩台筆電跑不動。主機 1 評估另案處理（見 2026-10-09 每日筆記）。
- **劇情喜劇的專屬規則**：頭套、老師不碰學生、上課鏡背景要有同學……MV 用不到。
- **他們的兩個 skill（編劇、Blender 預演）**：作者自己說裡面有舊說法，以 docs 為準。
